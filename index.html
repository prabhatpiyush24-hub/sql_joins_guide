What is a SQL JOIN?

A JOIN merges rows from two tables based on a matching column — like a shared customer_id in both a Customers and an Orders table. The JOIN type you choose controls which rows appear in the result.

📋 Customers (Left / Table A)

customer_idnamecity
1AliceNew York
2BobChicago
3CharlieLos Angeles

📋 Orders (Right / Table B)

order_idcustomer_idfood
1011Pizza
1022Pasta
10399 ⚠️Burger

⚠️ Key observation: customer_id 99 in Orders has no match in Customers. Charlie (ID 3) has no order. This mismatch is what makes each JOIN behave differently.

1 INNER JOIN

Returns only rows with a match in BOTH tables

📖 Theory

Returns rows where a matching value exists in both tables. Non-matching rows are excluded entirely.

🍽️ Restaurant Story

"You only get in if your name is on BOTH the reservation list AND the orders list."

✅ Alice → Pizza → IN
✅ Bob → Pasta → IN
❌ Charlie → no order → OUT
❌ ID 99 → no reservation → OUT

💻 SQL

SELECT c.customer_id, c.name,
       o.food, o.amount
FROM Customers c
INNER JOIN Orders o
  ON c.customer_id = o.customer_id;

📊 Result

customer_idnamefood
1AlicePizza
2BobPasta

✅ Use when you only want rows with matching data on both sides — e.g., customers who have actually placed orders.

2 LEFT JOIN (LEFT OUTER JOIN)

All rows from the left table + matched rows from the right

📖 Theory

Returns ALL rows from the left table. Matching rows from the right fill in; non-matching right rows become NULL.

🍽️ Restaurant Story

"List ALL reserved customers — order or not."

✅ Alice → Pizza → shown
✅ Bob → Pasta → shown
✅ Charlie → NULL food → shown (empty plate!)
❌ Stranger #103 → excluded

💻 SQL

SELECT c.customer_id, c.name,
       o.food, o.amount
FROM Customers c
LEFT JOIN Orders o
  ON c.customer_id = o.customer_id;

-- Anti-join: find customers with NO order
-- Add: WHERE o.customer_id IS NULL;

📊 Result

customer_idnamefood
1AlicePizza
2BobPasta
3CharlieNULL

✅ Use when you want all records from your primary table, even if no related data exists — e.g., customers without orders.

3 RIGHT JOIN (RIGHT OUTER JOIN)

All rows from the right table + matched rows from the left

📖 Theory

Returns ALL rows from the right table. Non-matching left rows become NULL. It is the mirror image of LEFT JOIN.

💡 Most developers rewrite RIGHT JOIN as a LEFT JOIN by swapping table order — same result, more readable.

🍽️ Restaurant Story

"Show ALL orders — reservation or not."

✅ Alice → Pizza → shown
✅ Bob → Pasta → shown
✅ Burger (ID 99) → NULL name → shown
❌ Charlie → no order → excluded

💻 SQL

SELECT c.customer_id, c.name,
       o.food, o.amount
FROM Customers c
RIGHT JOIN Orders o
  ON c.customer_id = o.customer_id;

📊 Result

customer_idnamefood
1AlicePizza
2BobPasta
NULLNULLBurger

✅ Use for auditing — e.g., find orders that don't belong to any known customer (potential data errors or fraud).

4 FULL OUTER JOIN

All rows from both tables — NULLs fill the gaps

📖 Theory

Returns ALL rows from BOTH tables. Where no match exists on either side, NULL fills the missing columns. Essentially LEFT JOIN + RIGHT JOIN combined.

🍽️ Restaurant Story

"I want the COMPLETE picture — every reservation AND every order, matched or not."

✅ Alice + Bob → matched
✅ Charlie → NULL food
✅ Burger (ID 99) → NULL name
Nobody is left out.

💻 SQL

-- PostgreSQL / SQL Server
SELECT c.name, o.food
FROM Customers c
FULL OUTER JOIN Orders o
  ON c.customer_id = o.customer_id;

-- MySQL workaround (no FULL OUTER JOIN):
SELECT c.name, o.food FROM Customers c
LEFT JOIN Orders o ON c.customer_id = o.customer_id
UNION
SELECT c.name, o.food FROM Customers c
RIGHT JOIN Orders o ON c.customer_id = o.customer_id;

📊 Result

namefood
AlicePizza
BobPasta
CharlieNULL
NULLBurger

5 CROSS JOIN

Every row from Table A paired with every row from Table B

📖 Theory

Produces the Cartesian product — no ON clause needed. If Table A has M rows and Table B has N rows, the result has M × N rows.

🍽️ Restaurant Story

"Show every customer paired with every dish — every combination."

3 customers × 3 dishes = 9 rows
Alice+Pizza, Alice+Pasta, Alice+Burger,
Bob+Pizza, Bob+Pasta … and so on.

⚠️ Warning: 1,000 × 1,000 rows = 1,000,000 results. Always test on small data first!

💻 SQL

-- Modern syntax
SELECT c.name, d.dish_name
FROM Customers c
CROSS JOIN Dishes d;

-- Older equivalent syntax
SELECT c.name, d.dish_name
FROM Customers c, Dishes d;

📊 Sample Output (3×3)

namedish
AlicePizza
AlicePasta
BobPizza
CharlieBurger
… 5 more rows…

✅ Use for generating combinations — products × sizes, test data, shift scheduling matrices.

6 SELF JOIN

A table joined with itself using aliases

📖 Theory

A table is joined with itself. You must use table aliases to distinguish the two instances. Perfect for hierarchical data where a foreign key references the same table's primary key.

🍽️ Restaurant Story

The staff table has everyone — but the manager_id column points back to another row in the same table.

emp_idnamemanager_id
1Alice3
2Bob3
3Charlie 👑NULL

💻 SQL

-- 'e' = employee, 'm' = their manager
-- Both aliases point to the SAME table
SELECT
  e.name    AS employee,
  m.name    AS manager
FROM Employees e
LEFT JOIN Employees m
  ON e.manager_id = m.emp_id;

📊 Result

employeemanager
AliceCharlie
BobCharlie
Charlie 👑NULL

✅ Use for org charts, category trees, social network connections, or comparing rows within the same table.

Quick Reference Summary

JOIN Type Left-only Matched Right-only Best Used For
INNER ❌✅❌ Strict matches — orders with known customers
LEFT ✅✅❌ All from left, even without a match on right
RIGHT ❌✅✅ All from right — auditing unmatched orders
FULL OUTER ✅✅✅ Full reconciliation — compare two datasets
CROSS —All combos— Generate combinations — sizes × colors × products
SELF —Same table— Hierarchies, org charts, same-table comparisons

✅ Best Practices

• Always alias tables (c, o, e)
• Start with INNER JOIN, switch only when needed
• Index your JOIN columns for performance
• Use IS NULL after LEFT JOIN for anti-joins

❌ Common Mistakes

• Forgetting the ON clause (accidental CROSS JOIN)
• Joining on non-indexed columns (slow scans)
• Using = NULL instead of IS NULL
• WHERE on right table column converts LEFT → INNER
